# 廖浩楠 · 云计算 / AI 运维 作品集

> 大专·云计算技术应用专业｜目标岗位：初级云运维助理 → 私有化 AI 运维
>
> 思路很直白：先把本地能跑的东西跑通，再让它们互相咬合，形成一条能自洽的链路，而不是三个互不相干的 demo。

## 一条完整的链路

```
本地大模型环境  →  服务监控（保活 + 留日志）  →  AI 日志归因（读懂日志）  →  巡检日报（主动汇报）
```

四个项目不是并列的，是串起来的：环境是底座，监控保证它活着并且留下证据，日志分析把证据变成结论，巡检日报把结论变成定期交付物。

## 项目

### 1. [learn-ollama-demo](https://github.com/3160627393/learn-ollama-demo)
本地 Ollama 环境跑通的最小 Demo。Python 调用本机大模型拿到回答，全链路装在本机 D 盘。

- 环境：Python 3.13 / Git 2.56 / VS Code / Ollama 0.40，全部指定安装路径，避开 C 盘空间不足
- 对比了三个模型的实际表现并留档：`qwen`（4B）会把 Nginx 编成"上传网页的服务器"，`qwen2.5:0.5b` 秒回但啰嗦，`qwen2.5:7b` 4 秒给出准确解释
- 结论：小模型能跑通流程，真干活要 7B

### 2. [ollama-monitor](https://github.com/3160627393/ollama-monitor)
Ollama 服务监控：四层体检 + 异常自动拉起 + 定时任务。

- 四层：端口 → HTTP 接口 → 模型就绪 → **真跑一次推理**
- 踩坑记录：只查端口会误判，端口通了 HTTP 层可能还没就绪，改成"等接口真正可响应"
- 故障注入实测：强杀进程 → 12 秒内自动恢复 → 全绿，日志留档
- 挂成 Windows 计划任务，每 5 分钟一轮，`pythonw` 静默运行

### 3. [ai-log-analyzer](https://github.com/3160627393/ai-log-analyzer)
用本地 7B 模型分析日志故障，输出严重程度 / 根因 / 影响 / 处理建议，落 Markdown 报告。

- 三层结构：规则提取异常片段 → 模型归因 → **代码兜底纠偏**
- 兜底是有意设计的：模型输出不稳定，同一份日志可能判"严重"也可能漏掉"已恢复"，所以恢复判定、数据格式这类关键结论由代码强行约束
- 实测：PostgreSQL"连接池耗尽 → 连接拒绝 → OOM 被杀 → 重启恢复"链条识别正确，4 秒出结果

### 4. [host-inspection](https://github.com/3160627393/host-inspection)
主机巡检 AI 日报：采集本机指标 → 规则判定 → 7B 模型解释 → 出一份能直接发出去的日报。

- 三层分工：PowerShell 采集原始数字、代码做阈值判定与日志统计、模型只负责解释和排优先级
- **命令白名单**：模型编过 `delvol C:\Temp` 这种不存在的命令，因此维护了一份真机验证过的命令库，白名单外的动作自动标注"待人工确认"
- 实测：C 盘 94% 触发空间风险、连续运行 41 天触发重启建议，模型 4 秒给出带命令的处理建议
